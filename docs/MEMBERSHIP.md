# 账号、兑换码及按天会员

## 部署配置

复制 `.env.example` 为 `.env`，配置 PostgreSQL、Better Auth 的公开 URL 与至少 32 字符随机密钥、SMTP、私有 S3 桶和另一份至少 32 字符的卡密摘要密钥。卡密摘要密钥应持久保管，改动会导致此前卡密无法兑换。对象存储凭证只保存在服务端，不配置公共读权限。邮件发送失败会使注册验证不可用，不提供绕过验证的生产开关。

部署环境初始化需要安装依赖、生成与当前 schema 对应的 Prisma 客户端及执行数据库迁移：`npm install --ignore-scripts`、`npm run db:generate`、`npm run db:deploy`。这些是部署准备步骤，不应通过构建代替。执行脚本时须由运行环境注入 `.env` 变量，例如 Node 20+ 使用 `node --env-file=.env scripts/grant-admin.mjs user@example.com`。

管理员先通过网页注册并验证邮箱，再由部署者运行 `admin:grant` 指定邮箱。网站不允许用户自行指定角色。Linux 环境需要可用的中文字体，设置 `EXPORT_FONT_PATH` 指向 Noto Sans CJK 字体文件。导出上限为 200 × 200 格，每格 30 像素；服务端需预留约 300 MB 图像处理内存，平台请求超时至少 120 秒。

上线前将 `NEXT_PUBLIC_SOURCE_URL` 配置为当前部署版本的完整修改源码地址。保留上游 LICENSE 和版权；只提供上游仓库链接不足以提供本版本源码。

## 业务规则

游客可生成预览与编辑；正式 PNG/CSV 导出须登录、验证邮箱且会员未到期。会员有效期内不限导出，不预占、不扣减次数。兑换码的 `durationDays` 表示开通天数（1–36500，常见 7/30/90/365 天）；批次的 `expiresAt` 是独立的兑换截止时间，留空仅表示不限兑换时间，不代表永久会员。服务端根据摘要查出实际天数，客户端不能指定。

首次兑换或已到期时，从服务端当前时间起算；有效会员续兑时，从原到期时间顺延。一天是连续 24 小时，数据库存 UTC，页面显示浏览器当地时间；剩余天数向上取整，仅供显示，权限严格以到期时间判断。管理员可以增减天数，操作必须填写原因，并保存调整前后到期时间及审计日志。缩短时间可使会员立即到期。兑换、人工调整使用 Serializable 事务、用户行锁和兑换码状态条件更新；同一码只能兑换一次，同一用户同时兑换不同码不会丢失天数。

每次成品包含图纸和采购清单；CSV 可选。相同账号、规范化网格、品牌、渲染版本及设置对应唯一任务，成功任务复用文件；不同账号不共享任务。导出及历史重新签名都校验有效会员，渲染上传后再次校验到期时间。签名链接有效期最多 5 分钟，且不超过会员到期时间。已签发链接无法因管理员后续缩短有效期或封禁即时撤销，最多受原签名期限限制。请求频率限制只用于保护服务，不是会员导出额度。

失败任务可以重试；部署者每分钟调用 `exports:recover`，或在后台恢复超过 10 分钟未完成的任务。恢复与完成通过状态、尝试标识及事务互斥，迟到任务不能覆盖新任务；成功、失败、重试均不改变会员有效期。对象存储成功但数据库失败可能留下未关联文件，建议周期性清理无成功任务引用的对象。成功文件需长期保留，不设置删除全部导出文件的生命周期规则。客户端色号和统计不可信，服务端依据原项目色板重算。

## 从旧次数版升级

`202610050002_duration_membership` 是新增表迁移：`Membership`、`MembershipEvent`、`MembershipCardBatch`、`MembershipCard`、`MembershipRedemption`。旧 `Wallet`、`Ledger`、`CardBatch`、`Card`、`Redemption` 表及原数据完整保留，不再用于当前业务。不会把旧次数自动当成天数，旧次数码也不会成为新会员码。若已售出旧码，需要运营方先制定兑换或补偿方案，再按新后台补发会员码/调整天数。当前环境未配置数据库，未执行真实迁移。

升级前备份数据库，执行 `db:deploy` 和 `db:generate`；禁止用 `db push` 重建或清理旧表。所有账号及原历史导出保留。旧 `/api/credits/redeem` 返回 410，引导刷新到会员兑换入口。

管理后台可生成最多 500 张卡，明文仅在生成响应中返回，保存摘要和尾号。页面清除或刷新后无法再次获取明文。禁止记录请求体、卡密或邮件验证链接。制卡响应丢失不能恢复明文，可按批次定位未使用卡密并逐张禁用，再生成新批次。

## 接口及验证

- `/api/auth/*`：Better Auth 邮箱注册、登录、验证、重置密码和会话。
- `GET /api/me`：会员到期时间、是否有效、剩余天数及最近 50 条兑换、会员变更、导出任务。
- `POST /api/membership/redeem`：`{ code }`，每账号每分钟最多 5 次尝试，返回实际会员天数及兑换后的到期时间。
- `POST /api/exports`：原编辑器网格、尺寸、品牌、设置；最多 4 MB，每账号每分钟最多 10 次。
- `GET /api/exports/:id`：有效会员获取账号自己的成功任务下载链接。
- `/api/admin`：管理员查询用户/兑换码/会员变更/审计及制码、禁用、有效期调整、封禁、任务恢复。制码请求使用 `durationDays`，有效期调整使用 `days`（非零整数）。列表每页 50 条。

写入业务接口校验 Origin，认证库校验自己的 CSRF；数据库限流适用于多进程部署。PWA 不缓存私人页面或 API。升级已有 PWA 时检查旧 Service Worker 是否仍控制页面，必须验证用户切换后看不到前一账号数据。

运行 `npm run test:membership` 验证规范化、摘要、首次兑换、续期、到期边界、并发兑换、有效期内多次导出、失败恢复、管理员调整及 PNG/CSV 渲染；这是直接执行 JavaScript 的测试，不编译项目。仅在独立测试数据库迁移完成后设置 PERLER_INTEGRATION_DATABASE_URL（不要指向生产库），再运行 `node --env-file=.env --test tests/postgres.integration.mjs` 进行真实并发事务测试。上线验收还需通过现有应用验证邮件全流程、两个账号隔离、管理权限、移动端导出及 PNG 的中文/色号/数量；不要用编译成功替代这些验证。

监控数据库事务失败、任务超时数量、邮件失败、存储错误及会员变更记录不一致；数据库与私有对象存储分别备份。本站提供在线导出服务，无法阻止用户截图或运行开源项目。
